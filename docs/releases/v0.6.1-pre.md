# ESP Ra.De. Native — v0.6.1-pre

Crash investigation, translated-handler coverage for the player-confirm/movement path,
and a 20,000-frame regression run. No ROM included.

## What changed

- Added translated handler `051B62`, reached after confirming a character and moving
  through Stage 1. Before this change the SDL loop stopped with
  `m68k: no translated code at 051B62` at frame 5276; from the player's side the window
  simply closed.
- Added deterministic SDL test inputs: `--confirm FRAME`, `--automove`, `--autobomb`.
  Existing inputs remain `--coin`, `--start`, `--autofire` and `--frames`.
- Added `docs/milestones/09-crash-investigation.md` and a crash/coverage regression
  command in `tests/README.md`.

## Crash investigation result

The local Windows Error Reporting history has six `esprade.exe` dumps from
18:42–18:45 on 2026-10-31: one `c0000005` access violation at `esprade.exe+0x1a55`
(write to `0x18ac4b3fb80`) and several `c0000374` heap-corruption reports. Those dumps
predate this build and the current commit; the heap-corruption records are consistent
with the rotation-buffer bug already fixed before v0.6.0.

No `c0000005` or heap-corruption dump was produced by the current source. The exact
reported 63-second access violation was **not reproduced**; this release does not claim
it is fixed. What was reproduced is the missing-handler termination above, which looks
like a crash from the player's side.
